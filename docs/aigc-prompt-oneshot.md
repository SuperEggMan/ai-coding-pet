# 一次生成：桌宠八态动作设定表

给 AIGC 出图工具**一次提问**用。下面「正向提示词」整段复制粘贴，配上「反向提示词」和参数即可。

为什么做成一张设定表而不是分八次出图：八格在同一次生成里产出，**画风、配色、五官、头身比天然一致**。分八次出图最容易翻车的就是一致性漂移，而交叉淡入的过渡会把漂移放大成「闪」。

---

## 参数

| 项 | 值 |
|---|---|
| 画幅 / 比例 | **2:1**（如 2048 × 1024） |
| 参考图 | 你的角色定妆图（一致性靠它锁死） |
| 参考强度 | 偏高（保角色，不保构图） |
| 出图张数 | 1 |

## 正向提示词

```
一张 2 行 4 列共 8 格的角色动作设定表，每格是同一个角色的不同姿态。

角色：参考图中的角色。八格必须保持完全相同的画风、配色、五官、
头身比、体型和线条粗细，只有姿态和表情不同。

排版：严格 2 行 4 列的等分网格，格与格之间没有分割线、没有边框、
没有文字、没有标号。每格里角色水平居中，脚底靠近该格底部，
八格中角色的绘制比例一致。

背景：整张图纯绿色 #00B140，完全纯色，无地面、无阴影、无投影、无杂物。

光照：柔和均匀的平光，八格一致。

八格的姿态按从左到右、从上到下的顺序依次是：

第 1 格：直立站着，重心居中，双手自然垂在身侧，平静微笑。

第 2 格：整个身体明显向前倾斜约 20 度并向上轻微拉长变高，
双手在身前小幅忙碌，眼睛半闭，专注的表情。

第 3 格：双手高举到头顶，捧着一小卷米黄色卷轴递向观众，身体向前倾，
抬头直视观众，眼睛睁得很大，充满期待的表情。

第 4 格：整个身体向左倾斜约 15 度，头也跟着向左歪，
双手向左右两侧张开摊平，疑惑的表情，嘴巴张成小圆形。

第 5 格：整个身体向上拉长变高并双脚离地跃起，双手举高欢呼，
眼睛闭成弯弯的月牙笑，腮红加深，开心的表情。

第 6 格：整个身体向下压扁变矮、向两侧摊宽到只有原来一半的高度，
肩膀塌下去，双手勉强还举着卷轴但已经垂下，
头顶挂一滴汗，眉毛下垂，疲惫委屈的表情。

第 7 格：身体向前折弯成深深的鞠躬，头几乎低到身体下方，
双手在身前合拢作揖，看不到脸只看到头顶。

第 8 格：完全脱力压扁摊平躺在地上，身体横向铺开摊成一坨，
宽度变成原来的两倍，四肢向外摊开，眼睛闭上，嘴巴微张。
```

## 为什么第 2、5、6、8 格要强调形变

你的角色是 1:1 头身比的软萌型，四肢短，**靠手臂角度做不出状态差异**。所以这四格用的是压扁拉长（squash & stretch）：

- 第 2 格 running：向上拉长 = 在赶工
- 第 5 格 done：拉长 + 离地 = 完成的喜悦
- 第 6 格 stale：压扁变宽 = 等到垮了
- 第 8 格 limp：极度压扁摊平 = 瘫

出图后如果这四格看着和第 1 格差不多，就是幅度不够。把数字写得更狠再生成一次，比如第 8 格改成「压扁到只有原来三分之一高，宽度变成三倍」。

## 拿到设定表之后

```bash
cd ai-coding-pet
python3 scripts/sheet-to-frames.py ~/Downloads/sheet.png src/skins/yunnuo/frames
```

脚本会自动做三件 AIGC 做不到的事：

1. **抠绿 + 去绿边**（despill，压掉主体边缘吃到的绿反光）
2. **八格统一缩放**（用同一个系数，所以刻意做的大小差异保得住，不会把「瘫」拉回和「待命」一样高）
3. **底边全部对齐同一条基准线** —— 这是消除「状态切换时角色上下跳」的关键

常用调整：

| 情况 | 做法 |
|---|---|
| 还有绿边 | `TOL=120 python3 scripts/sheet-to-frames.py ...` |
| 抠掉了角色本体 | `TOL=60 ...` |
| 图已经带透明通道 | `KEY=none ...` |
| 角色整体偏大/偏小 | `FIGURE=0.72 ...`（默认 0.78） |

然后建皮肤：

```bash
cp src/skins/_frames-template/skin.json src/skins/yunnuo/skin.json
# 把 skin.json 里 assets 八条的扩展名改成 .png，name 改成你的皮肤名
AICP_SKIN=yunnuo npm run poses    # 八态一屏，看差异和对齐
AICP_SKIN=yunnuo npm run demo     # 看真实状态流转和过渡
```

## 验收两条

**差异够不够**：`npm run poses` 的八格缩到 48px 还能分清是哪个状态。分不清就回去加大形变幅度。

**会不会跳**：`npm run demo` 里状态切换角色不上下跳。脚本已经做了底边对齐，理论上不会；真跳了就调 `skin.json` 里该状态的 `pose.figure.y`。

## 想要动图（可选，不急）

静态图在桌宠里已经会动 —— 引擎给了呼吸循环和状态间的过渡插值。动图只多给「角色内部的独立运动」（眨眼、四肢分开动、衣角飘）。

要上的话：拿**已经切好的那张静态图**去可灵图生视频，**首帧和尾帧都用这张图**（无缝循环的关键），运镜设**无/固定**，时长 5s。动作提示词只写小幅次要动作：

| 状态 | 视频动作句 |
|---|---|
| idle | 保持姿势不变，仅有轻微呼吸起伏，偶尔眨眼，镜头完全固定，背景纯绿色 |
| running | 保持前倾姿势，双手小幅快速摆动，身体轻微上下颠动 |
| awaiting_grant | 保持举着卷轴的姿势，卷轴轻微上下浮动，眨眼，期待地看着镜头 |
| done | 保持跃起姿势，身体轻微上下弹跳，笑容不变 |
| stale | 保持压扁姿势，肩膀轻微颤抖，汗滴缓慢滑落 |
| limp | 完全静止，仅胸口极缓慢起伏 |

### 八态动图：参考图 + 动作句（交给别的 AI 时按状态复制）

**参考图在 `docs/aigc-refs/<状态>-green.png`** —— 那是现有静态帧垫上绿幕 `#00B140` 的版本。必须用它，两个原因：①一致性靠参考图锁死，单独文生图重画一只必然跟其它状态脱节；②抠像脚本按这个绿色抠，透明底的图丢给图生视频会被填成白/黑底，抠不出来。

要 **mp4**，**不要 GIF**：GIF 只有 1 bit alpha，桌宠是透明窗口，边缘会变成锯齿硬边。

**每个状态的固定参数**：图生视频 / 首帧与尾帧都用该状态的参考图（无缝循环的关键）/ 运镜 **固定·无** / 时长 5s / 1:1。

**每条正向提示词都以这段开头**（不要省，省了角色就会走位、变形、出画）：

```
保持参考图中的姿势、构图和画面比例完全不变，角色始终在画面正中、脚底位置不动。
只做以下小幅动作，循环流畅、首尾能无缝衔接。背景保持纯绿色 #00B140 不变。
```

后面接这一句：

| 状态 | 动作句 |
|---|---|
| `idle` 待命 | 胸口极缓慢地呼吸起伏，约每三秒一次；头顶刷状毛和圆耳随呼吸慢慢轻晃；中途悠闲地眨两次眼，眼神平静放空。 |
| `running` 运行中 ⚠️**已废弃，改用下文「重做 running」** | ~~身体以每秒约两次的节奏轻微上下颠动，像在赶手上的活；胸前双手小幅快速上下交替忙碌，幅度很小、不离开胸口；头毛和耳朵慢半拍地轻晃；眼睛保持半闭的专注神情，中途快速眨一次。~~ 实际观感是「原地抖」，不是在办事，原因见下节。 |
| `awaiting_grant` 请奏 | 举着卷轴的双手保持不动，卷轴极轻微地上下浮动，像在等人来接；身体前倾幅度不变；眼睛睁大直视镜头，每两秒眨一次，眼神期待；头毛尖端轻轻抖动。 |
| `awaiting_choice` 请择 | 保持向左歪头摊手的姿势，头再极小幅度地左右来回摆两下，像在权衡；张成小圆的嘴保持不动；眼睛左右各瞟一次，最后回到镜头。 |
| `done` 复奏 | 保持跃起姿势，身体轻快地上下弹跳两到三次，落点越来越小；弯月牙的笑眼保持不变；头毛和耳朵随弹跳上下甩动，慢半拍回位。 |
| `stale` 久候 | 保持压扁摊宽的姿势，肩膀极轻微地一下一下颤抖；头顶那滴汗缓慢往下滑一小段；眉毛保持下垂，眼睛半闭无神，中途极缓慢地眨一次。 |
| `exiting` 请退 | 保持深深鞠躬的姿势，身体极轻微地上下起伏，像在屏息等回话；只看到头顶，头毛尖端轻轻晃动；全程不抬头。 |
| `limp` 瘫 | 完全静止摊在地上，只有身体极缓慢的起伏，约每四秒一次；偶尔一只脚尖抽动一下；眼睛闭着不动，嘴微张。 |

**反向提示词八个状态共用**：

```
镜头移动, 推拉, 摇镜, 变焦, 角色走动, 角色位移, 角色出画, 姿势改变,
换角色, 五官改变, 画风改变, 配色改变, 头身比改变,
新增道具, 特效, 粒子, 光斑, 文字, 速度线,
背景变化, 渐变背景, 地面, 阴影, 投影,
幅度过大, 夸张跳跃, 变形失控
```

**验收：缩到 84px（宠物在桌面上的真实尺寸）还能看出它在动，而且能看出是哪个状态。** 看不出就把幅度和频率写得更狠再出一版；晃得像跳舞就是幅度太大。

动作句的写法有个共同点：**只写次要运动，绝不改主姿势**。八态之间的区分度是靠静态设定表里的压扁拉长做出来的（见前文），动图只负责让它「像活的」。一旦让 AI 改姿势，它就会顺手把角色也重画一遍。

### 全部八态都要动图

把 8 个 mp4 按状态命名放一个目录里（`idle.mp4` `running.mp4` …），然后：

```bash
# 1. 找每个视频最适合的循环切点（和首帧最接近的那一帧）
scripts/find-loop-point.py ~/Downloads/kling

# 2. 转成 APNG（DURATION 用上一步给的值）
DURATION=2.0 SIZE=256 scripts/kling-to-frames.sh ~/Downloads/kling src/skins/yunnuo/frames

# 3. 接进 skin.json（改扩展名 + 删该状态的 loop）
scripts/adopt-anim.py src/skins/yunnuo

# 4. 验收
AICP_SKIN=yunnuo npm run poses
```

`SIZE=256` 不是默认的 512：宠物真实显示 84px，Retina 2x = 168px，256 已有 1.5 倍余量，而 512 的文件是它的三倍大（实测 4.3MB vs 1.5MB）。

`adopt-anim.py` 会在 skin.json 里留 `_loopBackup`，所以 `--revert` 能一键退回静态图对比效果。

**格式说明**：输出是 APNG 不是 GIF。GIF 只有 1 bit alpha，透明窗口上边缘会是锯齿硬边。APNG 支持全 alpha，Chromium 直接播。（本机 ffmpeg 8.1.2 有 apng 编码器、没有 libwebp，这条链已实测通过。）

用动图资产时**要把 `skin.json` 里该状态的 `loop` 字段删掉** —— 图里已经有动作，再叠引擎的循环会变成两套动作打架。

## 重做 running：原地快跑 · 多段

第一版 `running.mp4` 观感是「原地抖」而不是「在赶活」。**根因不在视频提示词，在静态基帧。**

`docs/aigc-refs/running-green.png` 里的姿态是**两脚并拢站着、双手在胸前捧着、眼睛半闭** —— 那是"站着搓手"。而图生视频只能加**次要动作**，不会（也不该）改主姿势。所以拿它当首帧，动作句里无论怎么写"上下颠动、双手快速摆动"，输出上限就是原地抖。

所以要分两步：**先重出跑步姿的静态基帧，再拿它出多段视频。**

### 先认清尺寸现实：「小腿嗖嗖」靠什么表现

角色是 1:1 头身比，腿在 1024 图里只占约 100px 高。缩到桌面真实的 84px 时，**腿只有 5~6 px**。所以「小腿嗖嗖」在真实尺寸下**不可能靠"看清两条腿交替"**，只能靠三样东西，按有效程度排序：

1. **围巾/头毛/耳朵向后飘** —— 速度感最强的信号。它们面积大、位置在头部，占的像素多。云糯脖子上那条青绿围巾是现成的速度载体，必须用上。
2. **腿部残影 / 运动模糊**，把两条小腿糊成一团扇形 —— 这才是"嗖嗖"的视觉本体，不是两条清晰的腿。
3. **身体上下颠 + 前倾**，剪影层面的变化。

写提示词时这三条都要点名，尤其第 1 条最容易被忽略而它最管用。

### 第一步：跑步姿静态基帧（图生图）✅ 已完成

> **成品已在 `docs/aigc-refs/running-green.png`**（旧的「站着搓手」版留作 `running-green.prev.png`）。
> 下面这段提示词和「调了三版才过」的记录留着，是为了下次给别的状态出图时不用重新踩。
>
> 三版的量化对比（团子度 = 头宽/总高，目标贴近 idle 的 0.723）：
>
> | 版本 | 团子度 | 宽/高 | 下半身展开 | 判断 |
> |---|---|---|---|---|
> | 现有 running（旧） | 0.646 | 0.674 | 0.76 | 剪影和 idle 几乎一样 → 观感就是「原地抖」 |
> | 第一版 | **0.555** ❌ | 0.903 | 1.25 | 动感够，但头身比/描边/五官全漂了 |
> | 第二版 | 0.654 ✅ | 0.754 | 0.99 | 一致性修好了，动感又没了（围巾缩回去、躯干不倾） |
> | 第三版 | 0.602 | **1.037** | **1.21** | 两头都够，采用 |
>
> **关键经验：第三版是拿第二版当参考图出的**，不是回到原始参考图。一致性一旦调对就锁在那张图里，
> 下一轮只放大姿态幅度，风格不会再漂。绕回原始参考图等于每次重赌一遍。
>
> 另一条：**判据是剪影**。84px 下用户看到的实质就是纯黑轮廓，所以提示词里必须写
> 「飘带要伸出身体轮廓之外、在剪影上能看见」这种话。旧版 running 之所以失败，
> 就是它的剪影和 idle 分不开 —— 表情画得再专注也没用，那个尺寸下看不见。
>
> 还踩到一个：**AIGC 会无视「无地面」画一条地面线。** 第三版底部有一条 2~3px 的横线，
> 抠像会把它当主体留下，桌面上就是一根莫名的横杠。它在双脚下方，直接把那几行填成背景绿即可，
> 主体一点不损失。出图后务必检查底部有没有横跨很宽的行。

参考图用 `docs/aigc-refs/running-green.png`，参考强度**偏高**（保角色，不保姿态）。1:1，出 1 张。

```
保持参考图中角色的画风、配色、五官、头身比、体型和线条粗细完全不变，只改姿态。

姿态改成【原地快跑的中段】：
身体明显向前倾约 25 度、重心压低；
两条短腿大幅前后分开跑动，前腿抬高到身体前方，后腿向后蹬直、
但后脚脚尖仍轻轻触到画面底部的地面基准线；
两条手臂前后大幅摆开，一手向前一手向后；
脖子上的围巾被跑动的风向身后水平吹起、拉长飘动；
头顶的刷状毛和圆耳向后倒；
眼睛睁开看向前进方向，嘴角上扬，努力又愉快的可爱表情，腮红加深。

角色水平居中。背景纯绿色 #00B140，完全纯色，
无地面、无阴影、无投影、无速度线、无尘土。
```

反向词在通用那套上再加：

```
站立, 双脚并拢, 双手在胸前, 静止, 走路, 跳跃,
残影, 运动模糊, 速度线, 尘土, 腾空过高, 双脚都离地
```

**「后脚脚尖仍轻轻触到地面基准线」这句不能省。** 管线里 `kling-to-frames.sh` 是按**画面底边**做 pad 对齐的，它不认角色的脚在哪。跑步中段如果两脚都腾空，角色会被整体下移，跟其它状态切换时就会上下跳。留一只脚在基准线上既是跑步中段又不破基线。真跳了再用 `skin.json` 的 `running.pose.figure.y` 补。

静态基帧**不要**画残影：残影留给视频段。基帧干净，图生视频时 AI 更容易"接着动"而不是重画。

### 第二步：多段视频

运行中状态动辄持续几分钟，单一个 2 秒循环重复几百遍会很假。所以拆成**一个主力循环 + 四个偶发段**，主力跑一阵随机插一段。

每段的固定参数都一样：**图生视频 / 首帧与尾帧都用 `docs/aigc-refs/running-green.png`**（无缝衔接的关键，事件段也要，播完才能顺畅淡回主力）/ 运镜 **固定·无** / 时长 5s / 1:1。

**五段共用的开头**（不要省）：

```
保持参考图中角色的画风、配色、五官、头身比和画面比例完全不变。
角色【原地跑动】，身体中心和脚下位置始终不动、不向任何方向位移、不出画。
两腿高速交替时用轻微的运动模糊把小腿糊成扇形残影。
循环流畅、首尾能无缝衔接。背景保持纯绿色 #00B140 不变。
```

### 实际接进来的五段（2026-09 落地值）

| 资产 | 源 | START | DURATION | 实测时长 | 备注 |
|---|---|---|---|---|---|
| `running` | running-v2 | 0 | 1.33 | 1.33s | 步频 4.0 步/秒，主力循环 |
| `running_burst` | running-v3 | 2.0 | 2.4 | 2407ms | 事件窗口内步频 4.6 |
| `running_wipe` | running-v4 | 1.2 | 2.3 | 2324ms | 汗珠保留（蓝色，不偏绿） |
| `running_stumble` | running-v5 | 2.0 | 2.4 | 2407ms | |
| `running_glance` | running-v6 | 1.4 | 2.4 | 2407ms | ⚠️ 权重压到 1，见下 |

**`running_glance` 是个反面教材**：AI 没有真的转头，只把表情改成了笑眼+张嘴。量过 84px 下的剪影 —— 事件段每帧到普通跑动最近帧的距离只有 **415px，比正常跑动自身的帧间变化 742px 还小**，也就是说这段**看不出任何变化**。表情在 84px 下只有 7px 的眼睛，压根传达不到。

教训：**偶发段的变化必须落在剪影上**，只改表情等于没做。要真效果得在提示词里要求「头部朝向改变」这种会改轮廓的动作，而不是「眼神/表情变化」。

### `pose` 的两个数别照抄

接完 apng 要重新量，因为它们跟素材绑死：

- **`y`（基线）**：`kling-to-frames.sh` 不裁主体，角色在画布里的垂直位置原样带过来。这批跑步姿的脚底在 **89.7%**，而其余状态统一在 **93.4%**，差 3px@84。旧 `y=-3` 是给"脚底齐平"的素材配的抬升量，换成新素材后要改成 **`y=0`** 才是同样的净效果。实测改完脚底差 0.5px。
- **`s`（表观大小）**：跑步姿横向展开，看着比 idle 小一圈，要往上提。但**有硬上限**：转轴在 stage 的 94%、角色顶部在 13.1%，`s` 每加 0.01 头顶上移约 0.81px。`s=1.14` 时只剩 1.8px 余量，叠上 `r=-3` 的旋转直接把耳朵裁在 100px 窗口外（实测踩过）。落到 **1.08**，留约 6px 余量，和 idle 的 3.5px 头顶余量相当。

顺带一条量法上的坑：**别用「上三分之一最宽行」当头宽指标去反推 `s`**。跑步姿的头是侧转下压的，这么量会低估头宽，据此换算出来的 `s=1.24` 严重过冲。改用「和已接受的旧素材对比 + 看会不会裁」来定。

**批量版**（工具支持一次排 5 个任务时，整段贴进去）：见下方「五段合成一次提交」。

**五段共用的反向提示词**：

```
镜头移动, 推拉, 摇镜, 变焦,
角色向前位移, 角色移出画面, 角色缩小, 角色变大,
换角色, 五官改变, 画风改变, 配色改变, 头身比改变,
双脚并拢站立, 停下不跑, 走路, 跳跃, 原地打转,
速度线, 粒子, 光斑, 尘土, 文字, 特效,
背景变化, 渐变背景, 地面, 跑道, 阴影, 投影,
幅度过大, 肢体错位, 多余的腿, 变形失控
```

`速度线 / 尘土 / 粒子` 必须写进反向词，这不是审美偏好：它们是绿幕上的**额外不透明元素**，抠像会把它们当主体留下来，最后桌面上会飘着几根莫名的白条。

`角色向前位移` 也必须写。"跑步"这个词天然诱导 AI 让角色跑出画面，一旦位移，抠出来的动图里宠物会在窗口里乱跑，而窗口只有 100px。

### 段落怎么调度

```
主力 A 循环 8~20s（随机）
  → 随机插一段 B/C/D/E，播 1.5~3s
  → 播完淡回 A
```

权重建议 **冲刺 2 / 抹汗 2 / 回头 2 / 踉跄 1**。踉跄最抢戏，给少点才显得是偶然。跑得特别久（比如超过 2 分钟）可以调高抹汗和踉跄的权重，顺带表达"跑久了会累"。

### 要用上多段，还差两处改动

1. **`kling-to-frames.sh` 的 `STATES` 是固定的八个状态名**，`running_burst.mp4` 之类不在里面，会被当"缺输入"跳过。需要加一个额外名单（比如 `EXTRA="running_burst running_wipe running_stumble running_glance"`）。
2. **渲染层缺 running 的段落调度器。** 底层能力已经有了 —— `FramesRenderer.playFrame(asset, holdMs)` 会临时换一张资产、到时自己淡回当前状态的基帧，`idle_chew` 就是这么用的。但调度器 `startIdleSkits()` 硬编码只在 `state === 'idle'` 时触发、且只认 `idle_chew` 这一个资产名。需要一个同构的 running 版本，读 `skin.assets` 里 `running_*` 开头的全部资产、按权重随机插播。

### 验收

缩到 **84px**（桌面真实尺寸）还能看出「它在快跑」，判据就是那三条：**腿糊成一团 + 围巾水平飘 + 身体上下颠**。看不出就把步频和围巾幅度写得更狠再出一版。

反过来，如果出现下面任一情况就是废片，别将就：角色在窗口里位移、画面里有速度线或尘土或地面线（都会被抠成白条）。

### 抠像的两个坑（都已在脚本里修掉，但要知道为什么）

**坑一：抠像色不能写死 `#00B140`。** 提示词里写的是这个，但视频工具吐出来的绿常常不是
（实测一段是 `#069040`、另一段首帧是 `#07A343`，差到 39）。写死 key 色就得靠加大容差去够，
而容差一大就出坑二。`kling-to-frames.sh` 现在默认 `KEY_COLOR=auto`，**每个视频各自从首帧四角取样**。

**坑二：容差大会把角色的深色线条抠穿。** 这个极其反直觉：深棕在 RGB 欧氏空间里离暗绿很近 ——
`RGB(93,69,63)` 到 `#00B140` 的归一距离只有 **0.32**，而脚本原来的 `similarity=0.30 + blend=0.12`
正好覆盖到 0.42。结果是**眼睛、眉毛、嘴被削成半透明**，桌面上两个透视孔，而且完全不会报错，
很难联想到是抠像干的（实测第一版 running 就是这样，16 帧里 5787px 空洞）。

所以硬规矩：**`similarity + blend` 必须小于 0.25**。现在默认 `0.12 + 0.08 = 0.20`，留了余量。
配合自动取样的 key 色，背景那头也够（实测四角最大归一距离 0.059）。

试过 `chromakey`（只比色度、不看亮度，理论上正好治坑二）——**不行**：这个角色是米白+薄荷色，
色度本身很低，`chromakey` 容差一过 0.18 就把角色整个吃掉（主体面积 20118 → 7032 → 518 → 0）。

**顺带一条**：`despill` 保持默认关。它是全局去绿，会把薄荷绿耳朵洗成灰蓝（实测
`(202,227,210) → (210,214,219)`，84px 下一眼看出不对）。留下的绿边只在 1px 亚像素轮廓上，
缩到 84px 压根看不见。宁可留看不见的绿边，不要肉眼可辨的错色。

### AIGC 会硬画运动弧，管线自动清

即使反向词写足了 `速度线, 尘土, 特效, 地面`，视频里还是会出现装饰物。实测第一段 running
的脚边有个**绿色月牙形运动弧**，12/16 帧都有，而且它的绿**和绿幕不是同一个绿**
（`RGB(112,168,128)`，归一距离 0.303），抠像抠不掉 —— 收紧容差治不了它，放宽又会抠穿眼睛。

`scripts/clean-apng.py` 专门收这个尾，`kling-to-frames.sh` 跑完会自动调用。判据两刀：

1. **和主体不相连 + 块内绝大多数偏绿** → 删。角色自己的绿（薄荷耳朵、头顶毛）永远连在身上，
   不会被判成独立块；`running_wipe` 里刻意甩出的汗珠是白/蓝的，不偏绿，会保留。
   不偏绿的独立块**保留并告警**，交给人看一眼，脚本不擅自删。
2. **离主体 4px 之外的偏绿像素，不管 alpha 多低一律扫掉**。第 1 刀只覆盖 `alpha > 60` 的连通块，
   而绿装饰的半透明外圈（实测 alpha 中位数 3、最高 57）会漏出来，缩到 84px 后仍能看出一圈淡弧。

实测效果：删掉 13 个绿碎块 / 4550px + 扫掉 2067px 半透明淡绿，离主体 6px 外的残留归零。

**唯一治不了的**：运动弧**贴住腿**的那一小段（连通性判不出来，颜色又和薄荷色接近）。
所以出图时最好在提示词里再加一句「脚下不要任何弧形拖影或装饰线条」，从源头掐掉。

### 出片先体检：`scripts/check-clip.py`

一段废片转成 apng、接进皮肤、起 Electron 才发现不对，来回一轮十几分钟；而下面这些全都能在源视频上量出来。

```bash
scripts/check-clip.py ~/Downloads/kling/running_burst.mp4
scripts/check-clip.py ~/Downloads/kling            # 整个目录
```

它检位移、地面线、步频、循环切点、深色线条被抠穿、绿装饰（分「脱离主体（能自动清）」和「贴住身体（治不了）」），最后给一句「可以进管线 / 建议重出」。阈值按每帧像素算，基准取的是实测判定可用的第一段 running。

写这脚本时自己踩了三个判据坑，都记在脚本头部注释里：**步频必须按源帧率抽帧**（12fps 抽帧的奈奎斯特上限只有 6Hz，8 步/秒会被折叠成 1 步/秒，把明显在快跑的片子报成「原地抖」）；**「空洞」必须回查源色**（四肢围成闭环时会把一块背景绿圈在里面，那是正常结果）；**「贴身绿」必须先腐蚀掉轮廓**（每张图边缘都有一圈亚像素绿溢色，缩到 84px 看不见）。写完拿已知可用的第一段当对照组验过 —— 一个会把好片子判死的体检脚本比没有更糟。

### 事件段要用 `START`，不能按循环切点裁

主力循环从 0 截一个完整步态周期就行。但**冲刺/抹汗/踉跄/回头这些动作发生在片子中段**，从 0 截只会得到事件发生前的稳定跑动，把事件整段丢掉。

`kling-to-frames.sh` 加了 `START`（`-ss`）。`check-clip.py` 会直接告诉你某段该填多少：

```bash
START=2.0 DURATION=2.4 SIZE=256 EXTRA="running_burst" \
  bash scripts/kling-to-frames.sh ~/Downloads/kling src/skins/yunnuo/frames
```

实测第一段冲刺：整片测出来步频只有 2.2 步/秒（被前后的慢速铺垫拉低），只看 `START=2.0 DURATION=2.4` 的事件窗口是 **4.6 步/秒**（主力循环 4.0）。所以冲刺是成立的，只是 AI 主要靠前倾、瞪眼、围巾绷紧来表达，腿速只快 15% —— 84px 下这个差异本来也看不出，可视信号恰好就是围巾和剪影。

片段的播放时长不用手填：`adopt-anim.py` 会从 apng 实测总时长写进 `skin.json` 的 `segments.<名字>.ms`，渲染层按它插播完再淡回主力。硬编码在代码里必然和资产漂移 —— 短了把动作切在中间，长了把整段又播一遍。

### AIGC 硬画的运动弧：三刀清理

`clean-apng.py` 现在有三刀，第三刀是为「贴住身体」的那种加的：

1. **和主体不相连 + 整块偏绿** → 删（默认开）
2. **离主体 4px 外的偏绿像素**（不管 alpha 多低）→ 扫（默认开）
3. **贴在身上的细绿笔画** → 删，判据是**填充率**（面积/包围盒）。**默认关**，
   要用就 `STROKE_FILL=0.22` 单独给需要的那几段开 —— `exiting`（深鞠躬、只露头顶）的
   头毛发丝同样细长，会被一起删掉、在头毛里挖出 539px 的洞。两者面积区间完全重叠
   （发丝 158~190px、运动弧 22~594px），靠面积分不开，所以不做自动判断。
   目前只有 running 那几段的素材里有运动弧。

第三刀的判据来自实测：耳朵和头顶毛的填充率是 28%~51%（大块实心），而运动弧只有 9%~17%（细长曲线），阈值 22% 落在中间两边都有余量。删完再把它周围 2px 内的半透明淡绿一起扫掉，否则会留一圈虚点弧。

**为什么不按「在身体哪个高度」划区**：那样最省事（这个角色的绿只长在头上），但 `limp` 是摊平躺着的，耳朵会落到画面下半部分，按高度划区会把耳朵擦掉。填充率跟姿态无关，所以用它。

拿既有 8 态做过回归：最大损失 2.7%（`exiting` 鞠躬时最外侧的细发梢），其余全 0。

### 接进来之后要补一刀基线

`kling-to-frames.sh` **不裁主体**，它只把整个 1024 方帧等比缩到 256，所以**角色在画布里的垂直位置会原样保留**。现有四张 apng 的脚底都精确落在画布高度 **93.4%**（当初 `sheet-to-frames.py` 做过底边对齐），而这张新基帧是 **89.6%** —— 角色偏高 3.7%，84px 下约 3.1px。不补的话从别的状态切到运行中会看见它往上跳一下。

补法：`skin.json` 的 `running.pose.figure.y` 从 `-3` 改成 **`0`**（往下压 3.1px 抵掉偏移）。

同理要留意**表观大小**：新基帧头宽 474px，旧版 539px，看着会小一圈。等 apng 接好了在 `npm run poses` 检查台里跟 idle 并排量一下再决定要不要动 `pose.figure.s`（现在是 1.01）。

## 想换 3D 风格？先别动引擎

「3D」有两条路，成本差一个数量级。

### 路 A：3D **画风**的贴图（推荐先试这条）

还是走现在这套「设定表 → 抠绿 → 图生视频 → APNG」的管线，只是让 AIGC 出图时用 3D 渲染的观感。**渲染器一行都不用改**，因为对桌宠来说它始终是一张带 alpha 的图。

先只重出**一个**状态试水（建议 `done`，形变最大、最能看出风格差异），在 84px 下判断值不值得全套重做：

```
一个 3D 渲染风格的角色，保持参考图中角色的体型、配色、五官比例和姿态。
质感换成柔软的黏土 / 毛绒玩偶：表面有细微绒毛与磨砂质感，
边缘微微反光，柔和的三点布光，轻微的次表面散射让身体边缘透一点光。
不要卡通描边，不要平涂。
角色水平居中，脚底靠近画面底部。背景纯绿色 #00B140，完全纯色，
无地面、无阴影、无投影。
```

反向词在通用那套上再加：`卡通描边, 平涂, 赛璐璐, 线稿, 写实人类皮肤, 金属反光, 强高光`。

**注意一致性红线**：八态必须同一个风格。真要转 3D，八张得**一次生成设定表**重出（见本文开头那节），不能只换两三个状态——桌宠会在状态之间交叉淡入，风格不一致会被过渡放大成「闪」。所以试水那张只用来做决定，别直接装进去。

### 路 B：真的上 3D 模型（`model3d` 渲染器）

`src/renderer/renderers.js` 里的 `Model3DRenderer` 是**故意抛异常的空壳**，资产契约已经定好了：

- GLB 或 VRM，Y 轴朝上，单位米
- 每个状态对应一个动画片段名（`skin.states[x].clip`）
- 片段之间用 `AnimationMixer.crossFadeTo(state.in.ms)` 过渡
- three.js 必须放进本地依赖（CSP 是 `script-src 'self'`，不能走 CDN）

代价清单：要一个绑好骨骼的模型 + 8 段循环动画（AI 目前给不了可靠的绑定结果，基本得手工）、three.js 约 600KB、每只宠物一个 WebGL 上下文（桌面上可能同时有四五只）。

**收益在 84px 上几乎为零** —— 那个尺寸里 3D 模型和一张好的 3D 风格贴图看不出区别。真正只有 3D 能给的是「视角能转」和「动作可程序化混合」，而桌宠现在两个都不需要。

### 先量一下：宠物到底占多少像素

这是决定要不要上 3D 的唯一依据。实测 `idle.png`（1024×1024 贴图，主体实占 577×798）在桌面上的真实渲染：

| | 84px（逻辑像素） | 168px（Retina 物理像素） |
|---|---|---|
| 角色实占 | **47 × 65 px**，不透明像素 2519 个 | 95 × 131 px |
| 一只眼睛 | 7.4 × 5.7 px | 14.8 × 11.5 px |
| 腮红 | 9 px 宽 | 18 px |
| **次表面散射的边缘透光带** | **1 px** | 2 px |

3D 的招牌效果（次表面散射、柔和高光、AO、绒毛）全部落在 1~2 像素上，**在感知阈值以下**。47×65 里能活下来的只有四样：**剪影、大色块、大面积明暗渐变、动作幅度** —— 而这四样现有 2D 贴图已经全有。

所以结论：**3D 的价值不在"更好看"，在"2D 做不到的交互"**（转头看鼠标、动作幅度跟真实数据联动）。想要前者就别碰 3D。

### 试过并撤掉的方案：朝光标倾身

既然这个尺寸下唯一看得清的是剪影，那就让剪影动 —— 按光标方向给宠物 ±4.5° 的倾角
和 ±3px 横移（做在 `.svg-host` 那一层，夹在 `.stage` 的手势动画和引擎位姿之间，
两边都不用改），远了衰减到 0 顺带得到"靠近才理你"。

**实现过，观感不好，已完整撤除。** 记在这里是为了别再重做一遍：数值上它确实在动
（实测左右满幅 ∓4.5°、正上方 0°、1200px 外归零），但真用起来宠物一直随光标晃，
像在抖，不像在看你 —— 缺的是**头部朝向**，而整体旋转给不了这个。真想要"看向你"
得走路 A（多朝向贴图）或路 B。

所以顺序是：**先走路 A 看效果，除非明确要转视角，否则不要碰路 B。**
